# How We Reduced AI Detection From 86%–100% Down to ~0% AI (And How to Build a Free Web App for Students)

This guide documents the exact technical pipeline, controlled A/B experiments, inference hyperparameters, automated factual-safety guards, and post-processing rules used on `RDRS_MIS_Internship_Report.tex` (`59` pages, `112` narrative prose blocks, `~7,485` words) to pass modern AI content detectors without sacrificing technical accuracy, citations, or document formatting.

It also provides a complete architecture blueprint for turning this workflow into a free web application that students can use on essays, theses, and reports.

---

## 1. The Core Discovery: Why Prompt-Engineering General LLMs Fails

Most "AI humanizer" prompts (asking Claude, GPT, or Gemini to *"vary sentence length, avoid em-dashes, write casually, cut transition words, and match human burstiness"*) fail against modern neural classifiers such as Sapling, GPTZero, and Pangram.

Those detectors do not merely count banned buzzwords (`delve`, `comprehensive`, `landscape`). They score the underlying **token-level conditional log-probability and perplexity curvature** across sliding windows of text. Even when a general RLHF assistant adopts simpler vocabulary, its probability distribution over next tokens still matches the smooth, predictable manifold of an RLHF instruction-tuned model.

### Our Controlled A/B Experiment on This Report

We proved this directly by running three versions of the exact same `RDRS_MIS_Internship_Report` text through **Sapling AI Content Detector** (`https://sapling.ai/ai-content-detector`):

| Pipeline Variant | Sapling Overall AI Score | What Happened |
| :--- | :--- | :--- |
| **A. Hand-edited / LLM-smoothed prose** (`apply_humanized_report.py` first pass: rewrote transitions to "tidy up" the humanizer's grammar) | **94.1% – 100.0% AI** across `32/33` narrative slices (`53.5%` on title-mixed slice `sc_01`, `2.7%` on abbreviations list `sc_06`) | Smoothing awkward phrasing back into clean academic clauses pulled every sentence straight back onto the LLM probability manifold. |
| **B. Raw `jialinyyzz/humanizer` (`humanizer-12b-Q3-QAT`) samples** (`test_raw_q3_1..4` and HF Space `test_hf_446`) | **0.0% AI** on **`5/5` samples** (`0% AI` across all `91` scored sentences) | The dedicated fine-tuned completion model broke the LLM perplexity signature completely. |
| **C. Raw `jialinyyzz/humanizer` + strict token-only fixes** (`apply_minimal_humanizer.py`: kept `>= 98%` of humanizer tokens/rhythm untouched; fixed only typos, numbers, URLs, slang, `\cite`, `\ref`, and LaTeX escapes) | **0.0% – 6.9% AI** across **`39/39` slices** (`28/39` at **`0.0%`**, `6/39` at `0.1%–0.3%`, `5/39` at `2.7%–6.9%`) | Retained the `0%` statistical signature while restoring full factual precision and clean 59-page LaTeX PDF compilation. |

Additional independent detector checks on the final **Variant C** text:
- **GPTZero (`https://app.gptzero.me/`, Model 5.0b):** Tested `sc_04.txt` (`116` words) anonymously -> **`100% Human` (`0% AI`, `0% Mixed`)** (*"We are highly confident this text is entirely human"*).
- **ZeroGPT (`https://www.zerogpt.com/`):** Tested three `~860`-word chunks:
  - `chunk_01.txt` (`5,445` chars): **`2.4% AI GPT*`** (*"Your Text is Human written"*)
  - `chunk_06.txt` (`5,607` chars): **`25.1% AI GPT*`** (*"Your Text is Most Likely Human written, may include parts generated by AI/GPT"*)
  - `chunk_09.txt` (`5,493` chars): **`61.1% AI GPT*`** (flagged technical `src/lib/...` file paths and HCVI formulas inside prose that scored `0.0%` on Sapling)

> **Golden Rule #1:** Never ask GPT/Claude/Gemini to "polish" or "smooth" the output of a dedicated humanizer model. A single pass of LLM stylistic cleanup destroys the statistical effect and drives AI detection scores right back to `99%+`.

## 2. The Model & Inference Setup (`jialinyyzz/humanizer`)

Standard chat LLMs fail because they were trained to maximize helpfulness and fluency. This pipeline uses **`jialinyyzz/humanizer`**, a specialized `12B`-parameter **completion** model trained specifically to rewrite AI drafts into natural human cadence.

### Weights & Hardware Sizing

From Hugging Face (`jialinyyzz/humanizer` and `jialinyyzz/humanizer-gguf`):
- **Full precision (`BF16`, `~24.5 GB`):** Best suited for high-VRAM GPUs.
- **Quantized local (`humanizer-12b-Q3-QAT.gguf`, `5.59 GB`):**
  - Exact size observed: `5,587,794,816` bytes
  - Verified SHA-256: `307bbfdf66fb22bf98aaa93fe7d54a713bf167e646073dc0cf10870b1525eb94`
  - Runs locally on Apple Silicon unified memory via Metal (`-ngl 99`) or a consumer GPU with at least `8 GB` VRAM (`Q3-QAT` / `Q4_K_M`).

### Critical Engine Requirement: Raw Completion, NOT Chat Template

`jialinyyzz/humanizer` is a **raw completion model** (`"chat": false`, `"style": "legacy"` in `prompt_format.json`).
- **Do NOT** wrap inputs in `<|im_start|>`, `[INST]`, OpenAI `messages: [...]` chat endpoints, or Ollama's default Modelfile chat templates.
- **DO** launch `llama.cpp`'s `llama-server` directly and call `/completion`:

```bash
llama-server \
  -m humanizer-12b-Q3-QAT.gguf \
  -c 8192 \
  -np 1 \
  -ngl 99 \
  --host 127.0.0.1 \
  --port 8080
```

Flags explained:
- `-c 8192`: Context window of `8,192` tokens (fits ~260–350 word chunks plus generous headroom).
- `-np 1`: Single parallel slot (`1` slot avoids splitting KV cache memory on 8–16 GB machines).
- `-ngl 99`: Offload all transformer layers onto GPU / Apple Metal (`~10.8 tok/s` observed on Apple Silicon with `Q3-QAT`).

## 3. Exact Prompt Format & Sampling Hyperparameters

Even small deviations in prompt whitespace or temperature weaken the humanizer output. Match `prompt_format.json` byte-for-byte.

### Prompt Construction (`prompt_format.json`)

```json
{
  "style": "legacy",
  "sep": "\n\n### Rewritten:\n\n",
  "fingerprint": "cc51d66b4c593fbe",
  "instr": "Rewrite the text below so it reads like a person wrote it, not a language model.\n\nReorganize it as you see fit. Vary sentence length on purpose. Cut hedging,\nthroat-clearing, and any sentence that only announces what comes next.\nPrefer the concrete word over the abstract one. It is fine to sound uneven.\n\nEvery fact, number, unit, date, name and quotation must survive unchanged.",
  "chat": false
}
```

Verify your prompt builder with a SHA-256 check on `"X"`:

```python
import hashlib

def build_prompt(draft: str) -> str:
    return PF["instr"] + "\n\n" + draft.strip() + PF["sep"]

assert hashlib.sha256(build_prompt("X").encode("utf-8")).hexdigest()[:16] == "cc51d66b4c593fbe"
```

### Exact Sampling Parameters

Do **not** lower temperature for "safer" grammar, and do **not** apply `repeat_penalty > 1.0` (which suppresses normal connective words and hurts natural flow):

```python
ptoks = len(tokenize(prompt))
dtoks = len(tokenize(draft))
room = 8192 - ptoks - 32
n_predict = max(256, min(math.ceil(dtoks * 2.5) + 64, 2048, room))

payload = {
    "prompt": prompt,
    "temperature": 1.0,
    "top_p": 0.95,
    "top_k": 0,          # disabled
    "min_p": 0.0,        # disabled
    "repeat_penalty": 1.0,  # disabled
    "n_predict": n_predict,
    # NO custom stop strings; stop naturally on model EOS
}
```

## 4. The Four-Stage Document Pipeline

Running a raw humanizer over a whole thesis, `.docx`, or `.tex` file directly will corrupt tables, break citations, alter numbers, and hit context limits. Split the workflow into four clean stages.

### Stage 1: Structure Extraction (`prepare_humanize_batches.py`)

Only rewrite **narrative prose paragraphs (`>= 12` words)** and explanatory list items. Explicitly skip and lock everything structural:
- Document headers, titles, tables (`tabular`, `longtable`), equations/math environments, formula cards (`\formulacard`), bibliographies, captions, figures, and verbatim schedules/appendices.
- Replace fragile inline LaTeX macros with compact human-readable placeholders before sending text to the model:
  - `Figure~\ref{fig:dishari-plan}` -> `Figure [fig:dishari-plan]`
  - `Table~\ref{tab:findings}` -> `Table [tab:findings]`
  - `Section~\ref{sec:official-schedule}` -> `Section [sec:official-schedule]`
  - `Chapter~\ref{chap:analysis}` -> `Chapter [chap:analysis]`
  - `\%` -> `%`, `~` -> space, `\textbf{...}` / `\textit{...}` / `\texttt{...}` -> plain text

### Stage 2: Smart Multi-Paragraph Grouping (`<= 260–350` words)

Rewrite consecutive prose paragraphs together in small groups rather than isolated single sentences:
- **Group target:** up to `3` consecutive `para` blocks totaling `<= 260` words (or up to `<= 350` words max). Grouping preserves inter-paragraph coherence without exhausting attention.
- **Keep special blocks solo:** list `\item` blocks, highlighted callout boxes (`\highlightbox`, `\keybox`), and long paragraphs (`>= 140` words) run alone.
- **1-to-1 Alignment Fallback:** After generation, split output on blank lines (`\n\s*\n`). If `len(output_paragraphs) != len(input_group)`, automatically fall back to rewriting each paragraph in that group individually so paragraph-to-line mapping stays exact.

### Stage 3: Automated Verification & Resampling Loop (`run_local_humanizer.py`)

Because `temperature = 1.0` introduces variance, run **up to 3 candidate attempts** per chunk and keep the lowest-penalty candidate that passes all three automated guards:

1. **Anti-Copy 5-Gram Guard (`copy_ratio <= 0.35`):**
   Tokenizes draft and output into alphanumeric words/Han characters/punctuation symbols and counts 5-gram overlap. If more than `35%` of output 5-grams match the draft verbatim, resample so detectors don't flag leftover AI phrasing.
   ```python
   UNIT = re.compile(r"[\u3400-\u9fff]|[^\W_\u3400-\u9fff]+|[^\w\s]")

   def copy_ratio(draft: str, out: str, n: int = 5) -> float:
       a = [t.lower() for t in UNIT.findall(draft)]
       b = [t.lower() for t in UNIT.findall(out)]
       seen = {tuple(a[i : i + n]) for i in range(max(0, len(a) - n + 1))}
       grams = [tuple(b[i : i + n]) for i in range(max(0, len(b) - n + 1))]
       return sum(g in seen for g in grams) / len(grams) if grams else 0.0
   ```

2. **Number & Fact Preservation Guard (`missing_numbers == []`):**
   Extracts every number/date/version/percentage (`\d+(?:[.,:/-]\d+)*`) from the input and flags any dropped value. Candidates with missing numbers receive a heavy `+10` penalty per dropped number and trigger a resample.

3. **Language-Drift & Shape Guard (`_is_bad_shape`):**
   Rejects outputs with:
   - Non-English CJK character drift (`> 5` Han/Kana/Hangul characters),
   - Chat assistant preambles (`"Sure,"`, `"Here is"`, `"Here's"`, `"###"`),
   - Extreme length collapse or bloat (`< 55%` or `> 175%` of draft word count),
   - Unrequested bulletization (`^(\*|-|\d+\.)\s+` when the draft had none).

### Stage 4: Surgical Token-Only Audit & Repair (`audit_rewrites.py` + `apply_minimal_humanizer.py`)

Never paraphrase the output after Stage 3. Instead, run automated checks for:
- **Dropped entities & acronyms** (`KEY_TERMS` list: proper names, project acronyms, technical identifiers, URLs, file paths)
- **Changed factual details** (in our report, caught and fixed: `"8% (declining balance) monthly charge"` -> `"8\% declining-balance service charge, repaid in 18 monthly installments."`; `"his friend Mahabub"` -> `"his colleague Mahabub"`; `"Code of Criminal Procedure (CRP)"` -> `"(CrPC)"`; `"NJera Kori"` -> `"Nijera Kori"`; `"sereshtha"` -> `"Serestha"`; mangled Enketo URL `kobo.toolboX.org` -> `\url{https://ee-eu.kobotoolbox.org/x/wzjSgzZ6}`; `"undo by mistake"` -> `"undo accidental edits"`; invented pronoun `"she"` -> `"who"`)
- **Single-word colloquialisms** (`things`, `stuff`, `guy`, `pptn`, `dicey`, `(sorry)`), replacing only the single token while keeping the surrounding words untouched
- **Syntax & typography safety:**
  - Convert `[fig:...]`, `[tab:...]`, `[sec:...]`, `[chap:...]` back to `\ref{...}`
  - Re-insert `\cite{...}` keys cleanly at the end of exact matching claims
  - Escape unescaped `%`, `&`, `#`, `_`
  - Re-wrap `\highlightbox{...}`, `\keybox{...}`, `\item `, and trailing `\\[6pt]`
  - Strip accidental `--` / `---` em-dashes

## 5. Architecture Blueprint for a Free Student Web App

You can turn this exact pipeline into a clean, low-cost web app (`Next.js / React` frontend + Python inference worker) for students.

### High-Level Architecture

```text
[Student Browser: Next.js / React + Tailwind]
   ├── Document Parser (.docx via JSZip/mammoth, .tex regex parser, .md, .txt)
   ├── Paragraph Extractor (skips tables, math, citations, equations, headers)
   ├── Side-by-Side Diff & Factual Shield UI (highlights numbers, dates, names, citations)
   └── Export Engine (.docx generator, .tex exporter, plain text copy)
           │
           ▼  (JSON chunks <= 260 words via WebSocket / SSE job queue)
[API Gateway & Job Queue: FastAPI + Redis / SQLite]
   ├── Exact prompt_format.json builder (SHA-256 fingerprint verified)
   ├── Resampling Loop (up to 3 attempts per chunk, 5-gram + number + shape guards)
   └── Rate limiter + queue ETA streamed live to the student
           │
           ▼  (POST /completion + POST /tokenize)
[Inference Worker: llama-server running humanizer-12b]
   └── Single GPU / Apple Metal host (or Hugging Face Space backend)
```

### Zero-Cost & Low-Cost Hosting Strategies

| Deployment Option | Cost to Run | Throughput & Hardware | Best Use Case |
| :--- | :--- | :--- | :--- |
| **Option A: Hugging Face Space** | Free / Community Space tier | Host or duplicate a Gradio/FastAPI Space running `jialinyyzz/humanizer` | Free public beta with queue management and zero server setup. |
| **Option B: Self-Hosted Single GPU / Campus Host** | Free on existing hardware (or low-cost GPU rental) | `humanizer-12b-Q3-QAT.gguf` (`5.59 GB`) ran at `~10.8 tok/s` locally on Apple Silicon Metal (`-ngl 99`) | Dedicated classroom or university portal with full queue control. |
| **Option C: Client-Side Upload + Server Streaming Queue** | Minimal server cost | Browser handles `.docx`/`.tex` parsing, math/table stripping, placeholder injection, diffing, and `.docx` re-assembly locally | Keeps backend 100% stateless (no student essays stored on disk, zero database cost, strong privacy). |

### Key UX Features Students Actually Need

1. **Format-Safe Parsing Before Inference:**
   Just like Dishari parses `.docx` XML client-side with `JSZip`, parse students' `.docx` or `.tex` uploads right in the browser, extract only body paragraphs, freeze tables/footnotes/equations/bibliographies, and inject `[CITE_1]`, `[REF_1]` placeholders automatically so references never break.
2. **Inline "Fact Shield" Diff View:**
   Automatically run the `missing_numbers` and `KEY_TERMS` (capitalized entities, citations, dates) check in the UI. Highlight any dropped stat or altered year in amber before download so a student never submits hallucinated thesis data.
3. **One-Click Paragraph Re-Roll (`temp = 1.0`):**
   If one paragraph comes back slightly too informal or still triggers a sentence warning on Sapling, let the student re-roll **just that single paragraph** (`260` words takes only seconds) rather than regenerating the whole document.
4. **"Minimal-Edit Only" Warning Banner:**
   Add an inline editor notice reminding students: *fixing spelling mistakes or single numbers is safe, but using Grammarly's "Rewrite for clarity" or ChatGPT to "polish" the output will raise AI scores back to 90%+.*
5. **Detector-Aware Built-In Readout (Without Bypass Tricks):**
   Display transparent local heuristics right next to the output:
   - Sentence-length variance (CV target `>= 0.50`)
   - 5-gram novelty ratio vs original draft (`copy_ratio <= 0.35`)
   - Number & citation retention (`100%` match indicator)

## 6. Reproducible Verification Checklist

Before trusting any humanizer web app build, validate every output against this checklist:

- [ ] `prompt_format.json` fingerprint check passes (`sha256[:16] == "cc51d66b4c593fbe"`).
- [ ] Model is invoked via raw `/completion` (`chat: false`), NOT `/v1/chat/completions`.
- [ ] Sampling uses `temperature=1.0`, `top_p=0.95`, `top_k=0`, `min_p=0.0`, `repeat_penalty=1.0`.
- [ ] `copy_ratio <= 0.35` and `missing_numbers == []` hold across all rewritten blocks.
- [ ] No post-generation LLM paraphrasing/polishing step touches sentence structure.
- [ ] Every `\cite`, `\ref`, table, equation, and verbatim appendix compiles unchanged (`tectonic` / `.docx` export with 0 errors).
